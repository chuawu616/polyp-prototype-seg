# Results

## Evaluation protocol

- **Train**: Kvasir + CVC-ClinicDB training split (1,450 images), PraNet split. **Test**: CVC-ClinicDB (62), Kvasir (100),
  CVC-300 (60), CVC-ColonDB (380), ETIS-LaribPolypDB (196) — 798 images.
- **Unified protocol** (all tables below): foreground probability resized to the GT size, binarised at 0.5, per-image
  Dice and IoU averaged per dataset. **mDice** = unweighted mean over the five datasets (the convention of the EMCAD
  paper's "polyp" column, 0.866 for EMCAD). In-domain = ClinicDB + Kvasir, out-of-domain = the other three.
- **Why re-evaluate.** The original scripts disagreed: the EMCAD / learnable / DINOv3 scripts used *soft* Dice on
  min-max-normalised maps, the non-learnable scripts *hard* Dice, and the V0/V3 scripts thresholded the foreground
  similarity alone (ignoring the background score the model was trained with). `orig. mDice` is the number the
  original script logged. Re-scoring changes 48 of 70 checkpoints by < 0.003; soft-Dice models all gain slightly
  (median +0.002, DINOv3 models up to +0.023), and the foreground-only
  rule of V0/V3 had under-rated them by up to +0.040. No ranking-level conclusion changes.
- **Provenance.** Every one of the 70 surviving checkpoints was loaded strictly into the refactored code
  (`tools/reevaluate_legacy.py`). For each checkpoint that has a training log, the original protocol reproduced the
  logged per-dataset Dice of one specific epoch to < 1e-4 (column *verified*). The four ✗ rows have no log
  (`fb88 re-run`, DINOv3 `last block, fine-tuned` and `smooth`) or lost code (`uncertainty gate`).
- **Model selection** used the test sets (inherited from the baseline code; there is no validation split), so all
  numbers are optimistic and best read as relative comparisons.
- **Noise level.** The same prototype configuration trained twice (fb88) gave 0.876 and 0.866; two linear heads with
  slightly different decoders gave 0.876 and 0.872. Differences below ≈ 0.01 are not significant.

Raw data: [`results/reevaluation.csv`](results/reevaluation.csv) (unified + original score, matched log/epoch) and
[`results/experiments_raw.csv`](results/experiments_raw.csv) (every logged run, from `tools/parse_logs.py`).
Tables are generated by `tools/make_tables.py`.

## Naming

| Tag | Meaning |
|---|---|
| `fbXY` | X foreground + Y background prototypes |
| `fhbXYZ` | X foreground prototypes, of which Y are *hard* (X−Y *easy*), + Z background prototypes |
| `warm10` | hard-prototype contribution warmed up over the first 10 epochs |
| *Learnable prototype* | the author's baseline: the EMCAD 1×1 head replaced by learnable cosine prototypes, nothing else changed |
| *blocks 2..12* | DINOv3 features of blocks 2, 4, …, 12 concatenated |

Reading the table:

- The **linear head** (0.872–0.876) and the **learnable prototype head** (0.865–0.876 over 10 prototype counts) are
  indistinguishable; the best prototype run (fb88) did not reproduce (re-run 0.866).
- No add-on — KL balancing, easy/hard specialisation, hybrid prototypes, a DINOv3 backbone — leaves the noise band;
  pixel-contrastive pre-training (fall-semester idea) costs 10 points.
- A frozen DINOv3 is far behind (ViT-S+/B/L 0.785 / 0.799 / 0.815); fine-tuned, it matches PVTv2 + EMCAD.
- Non-learnable prototypes are **below** the linear head: V3 ≈ its structure-loss-pretrained initialisation
  (best epoch 2), V0 −2.7, pseudo-label −1.5, pseudo-label + superpixel −2.5 points.
